# Isolated on-device verification

Application source commit: `f9c2abd` (documentation commits do not change the application). The review APK uses package `rocks.pkb.plektra.review.wordranking`, labelled **Plektra Ranking Test**, configured by an external local Gradle init script. The user's daily apps were not replaced.

Device: Titan2, Android16/API36. App UI language: English. Manual QWERTY was selected only in the review app and locale-based layout selection was disabled so ADB keycodes had deterministic characters. An initial attempt inherited the French AZERTY mapping and was discarded before recording; no application code was changed to fix the test setup.

## Test data and procedure

Sample One is the plain native text-editor fixture used for the launcher demonstration in [PR166](https://github.com/pkb-rocks/plektra/pull/166). This contribution has no dependency on the launcher. The fixture has no network permission or user accounts.

The isolated review app was seeded with two ordinary user-dictionary entries, `planer` and `planet`, each with frequency100. Its editable default-user list was empty. Usage counters were not seeded. Autocorrection and automatic first-letter capitalization were disabled only in the review configuration.

1. Focus the empty Sample One editor and type `plan`. The two fixture completions appear in order `planer`, `planet`.
2. Clear the fictional editor and type `planet ` three times through native Android keyboard events.
3. Clear it again and type the same prefix, `plan`. The two completions now appear in order `planet`, `planer`.
4. Verify both user-dictionary frequencies remain100. The personal usage signal changes the order; dictionary frequencies were not increased for the recording.
5. In review settings, open Auto-Correction and select **Reset learned word ranking**, then confirm **Reset**. Return to the fixture, clear it and type `plan`: the original completion order returns. This reset was checked before the recorded take.

The leftmost cell retains the current typed prefix `plan`; the comparison concerns the next two dictionary-completion cells. The recording does not claim that a completion replaces this current-word cell.

Events were generated by a standalone UiAutomation instrumentation helper restricted to Sample One and the isolated review keyboard/settings. It used `FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES`, checked test foreground and only accepted the fixed synthetic strings. No Enter/send command was injected. This verifies the real app/IME pipeline with injected events, not every physical-key or device-layout combination.

## Evidence and limits

The final English-captioned recording is23.84seconds. Status-bar128pixels are cropped, audio is absent and source timestamps/metadata are removed. All124native frames were visually checked; only the fictional fixture, its editor and the review keyboard are present. A foreground watchdog aborts recording if a non-test activity appears. The user reviewed and explicitly approved this final media for publication.

Actual ZIP round trips, invalid data, blocked writes and rollback were tested with RobolectricAPI33, not performed against personal phone data. No real conversations, contacts, documents, dictionaries or backups were used.

The original default/enabled keyboard configuration and accessibility-service settings were read before the test and checked for an exact match after restoration. The standalone instrumentation helper was uninstalled. Sample One and Sample Two were retained at the user's explicit request.
